本文对应源码版本 `1.0.9`，适用于 MaixCAM Pro 上的圆形定位与红、绿、黄、黑、蓝五色识别。程序上电进入模式3，持续采图、计算平均圆心并通过串口输出坐标。

工程由以下文件组成。

| 文件 | 作用 |
| --- | --- |
| [main.py](main.py) | 相机初始化、白平衡校准与加载、圆形检测、颜色分类、串口收发、屏显开关及主循环 |
| [gui.py](gui.py) | GUI，即屏幕上的按钮和滑条；处理触摸事件、绘制控件并刷新屏幕 |
| [app.yaml](app.yaml) | 应用信息，当前应用标识与名称均为 `scavenger_vison`，版本为 `1.0.9` |
| `app.png` | 应用图标 |
| `data/white_balance.json` | 设备运行后生成的白平衡参数文件 |

运行环境使用 Sipeed 官方 MaixPy 的 `camera`、`image`、`display`、`touchscreen`、`time`、`app` 和串口接口，以及 OpenCV 图像处理库 `cv2`、数组计算库 `numpy`。

启动顺序为：初始化 GUI 与串口 → 配置 OpenCV 单线程和 MaixVision 图像传输画质 → 打开相机并跳过30帧 → 加载已保存白平衡 → 创建控件 → 进入循环。每次循环先处理待执行校准、读取屏显指令和采图，再处理触摸、识别与坐标发送，最后按刷新周期提交屏幕。

相机采集尺寸为 `320×240`，输出 BGR 格式，即每个像素按蓝、绿、红顺序保存三个颜色分量。检测时缩放至 `240×180`，圆心和椭圆尺寸除以 `DETECT_SCALE=0.75` 后恢复到原始图像坐标。

GUI 使用 `320×320` 的逻辑画布，顶部240像素承载图像，底部80像素承载状态与控件；显示与触摸统一使用 `FIT_FILL`，将画布宽、高分别拉伸到屏幕宽、高以铺满屏幕。下文所有控件坐标均为该逻辑画布中的 `(x,y,宽,高)`，图像坐标原点在左上角，X向右增大，Y向下增大。

`process_frame()` 依次执行缩放、灰度转换、5×5平滑去噪、边缘提取、轮廓筛选和椭圆拟合；椭圆拟合是用一条椭圆贴合轮廓以取得中心和轴长。灰度边缘与饱和度边缘合并后，使用3×3椭圆形范围扩张再收缩以连接断点，并保留原始边缘像素。

| 筛选参数 | 原始320×240坐标下的门槛 | 当前240×180检测图中的门槛 |
| --- | --- | --- |
| 最小面积 `CIRCLE_MIN_AREA` | 1200平方像素 | `1200×0.75²=675`平方像素 |
| 最小周长 `CIRCLE_MIN_PERIMETER` | 120像素 | `120×0.75=90`像素 |
| 最大周长 | 555像素 | `555×0.75=416.25`像素 |
| 圆度 | 大于0.7；圆度定义为 `4π×面积÷周长²` | 大于0.7 |
| 轮廓点数 | 至少5个点以支持椭圆拟合 | 至少5个点 |

圆心筛选使用原始图像坐标：先取所有候选圆心的最小Y值；恰好一个圆心比该值低超过25像素时剔除该圆心；随后对保留圆心的X和Y分别取平均值作为输出。该筛选条件以外的候选集合整体参与平均。

`cv2.RETR_TREE` 会提取多层轮廓，圆环的内外边界可以各产生候选椭圆，因此屏幕“轮廓数”统计的是通过筛选的轮廓数量。输出坐标表示候选集合的平均中心。

`detect_circle_color()` 在候选椭圆内部取样：采样椭圆的轴长为拟合轴长的97%，横向和纵向每隔2像素取样一次。取色使用 HSV，即 H色相表示颜色类别、S饱和度表示颜色浓度、V明度表示亮暗；本工程采用 OpenCV 的取值范围 `H=0～179，S/V=0～255`。

| 颜色编号 | 屏幕名称 | 分类条件 |
| --- | --- | --- |
| 0 | 未知 | 最高颜色票数占采样像素比例小于18%，或采样像素少于20个 |
| 1 | 红 | `H≤10` 或 `H≥170` |
| 2 | 绿 | `35≤H≤85` |
| 3 | 黄 | `18≤H≤34` |
| 4 | 黑 | `V<black_level` |
| 5 | 蓝 | `90≤H≤135` |

红、绿、黄、蓝分类共同要求 `S≥70` 且 `V≥max(40,black_level)`。黑色门槛为 `black_level=max(30,min(80,white_level×0.25))`，其中 `white_level` 是校准时白纸三个颜色分量的平均亮度，默认参考值为200。

各颜色满足条件的像素分别计票，占比达到18%且票数最高的颜色成为该椭圆的结果。同一帧内的已知颜色汇总去重后显示；整体颜色集合连续3帧一致时显示名称，确认过程中显示“确认中”，检测为空时显示“未检测”，全部分类为0时显示“未知”。

当前颜色结果通过左上角文字显示；主循环的串口输出使用下文的 `0x02` 坐标帧，数据末尾保留字节为 `0x00`。

按钮操作在手指松开且触点位于对应按钮范围内时执行，滑条在拖动过程中更新。

| 控件与位置 | 显示内容 | 使用方式 |
| --- | --- | --- |
| 左侧第一个红框 `(0,0,60,64)` | 圆心 | 功能标识 |
| 左侧第二个红框 `(0,64,60,64)` | C Min / C Max | 点击切换滑条当前编辑的边缘阈值；C Min对应下限，C Max对应上限 |
| 左侧第三个红框 `(0,128,60,64)` | 模式3 | 当前工作模式标识 |
| 左侧第四个红框 `(0,192,60,64)` | 屏显开 / 屏显关 | 点击切换摄像头图像底图的刷新；关闭后文字每500毫秒更新，触摸逐帧检测 |
| 左侧第五个红框 `(0,256,60,64)` | 显示 | 点击切换边缘预览和原始彩色预览 |
| 底部滑条 `(80,294,140,18)` | C Min或C Max | 拖动修改当前选中的边缘阈值，滑条范围0～100，实际阈值为 `int(滑条值×255÷100)` |
| 右下按钮 `(210,263,104,28)` | 白平衡 | 以中心框内的白纸启动一次校准，成功后保存参数 |

`C Min/C Max` 是 Canny 边缘提取的两个门槛，Canny 按图像变化强度寻找物体边界。启动下限为50、上限为150；拖动后的上下限满足 `C Min≤C Max` 时按正常门槛顺序工作。滑条当前值采用整数映射，显示位置存在量化，例如滑条50对应实际阈值127。

“显示”按钮控制预览内容，程序的圆形与颜色识别流程持续执行；初始预览为边缘图。“屏显关”使摄像头图像及轮廓标记停留在最后一张底图，颜色、坐标、阈值、耗时、FPS、白平衡状态和控件按 `TEXT_REFRESH_INTERVAL_MS=500` 毫秒周期更新；控件变化和屏显切换触发即时重绘。采图、识别、坐标发送与触摸检测持续逐帧执行；再次点击同一红框即可恢复摄像头图像刷新。

每次启动时屏显开启，阈值恢复为50/150，预览恢复为边缘图。白平衡参数按文件加载。

文字直接叠加在图像上，模式名称位于左侧第三个红框。

| 文字 | 位置 | 含义 |
| --- | --- | --- |
| `颜色:红` 等 | `(65,2)` | 连续3帧确认后的颜色名称；同帧识别出的多个已知颜色按编号排列 |
| `阈值:50,150` | `(65,22)` | 当前边缘提取下限与上限 |
| `X:… Y:…` | `(65,42)` | 当前平均圆心的原始320×240像素坐标；检测为空显示 `X:-- Y:--` |
| `轮廓数:…` | `(65,62)` | 本帧通过圆形门槛的轮廓数 |
| `采… 算… 显…ms` | `(65,82)` | 分阶段耗时，单位为毫秒 |
| 白平衡提示或失败原因 | 从 `(65,166)` 起 | 白纸位置提示、校准提示或异常说明 |
| 版本号 | 图像区域右下方 | 当前源码版本 `v1.0.9` |
| 白平衡状态 | `(65,242)` | 待校准、已加载、校准中、已保存或失败阶段 |
| `FPS:…` | 画布右下角 | FPS，即每秒完成处理的帧数，显示上一完整循环计算的整数值 |

“采”统计相机读取耗时；“算”统计触摸读取、图像缩放、边缘与轮廓处理、颜色分类、坐标发送，以及图像刷新开启时的部分图像绘制；“显”统计剩余绘图、底图复制、文字、控件与 `display.show()` 调用。屏显关闭后，跳过绘图与屏幕提交的帧将“显”记录为0；文字刷新帧记录实际显示耗时。刷新周期从上一刷新帧开始计时，实际刷新发生在达到间隔后的处理帧。

屏幕中“采”和“算”来自当前帧，“显”和FPS来自上次完成的帧。FPS计算为 `int(1000÷max(完整循环毫秒数,1))`，完整循环包含屏显指令读取、采图、识别和GUI处理；执行白平衡校准期间主循环暂停，该校准耗时单独发生在FPS计时之前。屏显关闭后这些数值继续更新，`DEBUG_OUTPUT=True` 时控制台逐帧输出当前FPS与阶段耗时。

相机保持320×240采图，检测阶段使用240×180；OpenCV设置为单线程；显示使用持续存活的共享缓冲区；控件文字尺寸通过缓存复用；MaixVision图像传输画质设为70。设备端实际FPS以运行结果为准。

白平衡通过调整相机红、蓝通道增益，使白纸的三个颜色分量接近一致。中心采样框为 `WB_ROI=(128,88,64,64)`，位于原始320×240图像中。

1. 将均匀白纸放入当前光照下，覆盖画面中心采样框。
2. 点击“白平衡”，保持白纸和相机静止，程序执行采样与增益调整。
3. 状态显示“白平衡:已保存”后，参数已写入应用数据目录，下次上电自动加载。

每轮调整后跳过8帧，再采3帧取颜色分量中位数的平均值；最多执行8轮，最大分量与最小分量之比达到 `≤1.08` 时完成校准。有效像素要求每个分量至少20且最大分量小于250，有效像素占中心框至少50%，各分量标准差至多30；这些条件用于判断白纸亮度与均匀程度。

相机接口使用官方 `cam.awb_mode()` 和 `cam.set_wb_gain()`，图像来自 `cam.read()`。自动状态的初始增益回读可使用官方初值 `[0.134,0.0625,0.0625,0.1239]` 启动校准；工程兼容四个零的增益回读，最终以白纸图像的分量比例判断校准完成。

保存路径通过 `app.get_app_data_path()` 获取，实际文件为该目录下的 `white_balance.json`，通常对应当前应用的 `./data/white_balance.json`。文件写入临时文件、同步数据后替换正式文件；该应用数据目录的存储介质由设备系统挂载决定，参数随该文件持久保存。

文件结构示例如下，`gains` 的四项依次为红、绿色分支1、绿色分支2、蓝的相机增益，具体数值由现场校准产生：

```json
{
  "version": 1,
  "gains": [0.134, 0.0625, 0.0625, 0.1239],
  "white_level": 180.0
}
```

此处 `version=1` 表示参数文件结构版本，应用源码版本为 `1.0.9`。加载时校验参数结构并应用增益，成功显示“已加载”；校准异常时显示相机接口、写入增益、白纸采样或文件保存对应的失败阶段及具体原因，并尝试恢复原白平衡状态。

通信使用以下串口配置。

| 项目 | 当前配置 |
| --- | --- |
| 设备节点 | MaixCAM Pro 的 `/dev/ttyS0` |
| 波特率 | 115200 bit/s |
| 数据格式 | 8位数据、无校验、1位停止位，即8N1 |
| 接口封装 | `maix.v1.machine.UART` |
| 视觉板发送 | 检测成功后的9字节坐标帧 |
| 视觉板接收 | 单字节屏显开关指令 |

发送值采用原始二进制字节。串口工具选择“HEX发送”时，输入 `07` 会发送一个值为7的字节；MCU程序可直接发送 `uint8_t` 数组 `{0x07}`。

当前主循环调用 `comm.send_detect(0x02, Yuanxy)`，每帧检测到候选圆形后发送一次，帧长固定9字节：

```text
B3 B3 02 X_EXTRA X_BASE Y_EXTRA Y_BASE 00 5B
```

| 字节偏移（从0开始） | 长度 | 内容 | 含义 |
| --- | --- | --- | --- |
| 0～1 | 2 | `B3 B3` | 帧头 |
| 2 | 1 | `02` | 坐标消息类型；工作模式3使用该消息类型发送 |
| 3 | 1 | `X_EXTRA` | X坐标超过255后的补充值 |
| 4 | 1 | `X_BASE` | X坐标基础值，最多255 |
| 5 | 1 | `Y_EXTRA` | Y坐标超过255后的补充值 |
| 6 | 1 | `Y_BASE` | Y坐标基础值，最多255 |
| 7 | 1 | `00` | 当前坐标消息的保留字节 |
| 8 | 1 | `5B` | 帧尾 |

坐标还原公式为 `X=字节3+字节4，Y=字节5+字节6`。每个基础值达到255后，余量放入对应补充值，接收端以两个字节相加恢复坐标；实际图像中 `X=0～319，Y=0～239`。

例如中心为 `(300,120)`，X编码为 `45+255`，发送内容为：

```text
B3 B3 02 2D FF 00 78 00 5B
```

MCU接收端根据帧头寻找起点，收齐9字节后校验消息类型与帧尾，再按下式恢复坐标：

```c
uint16_t x = (uint16_t)frame[3] + frame[4];
uint16_t y = (uint16_t)frame[5] + frame[6];
```

接收方通过帧头、消息类型、固定长度与帧尾进行结构校验。每次检测成功产生一个坐标帧，检测为空时发送数量为0，因此接收方可记录有效帧到达时间表示坐标的新鲜程度。

屏显指令长度为1字节，直接发送下表内容：

| 指令字节 | 动作 | 图像与触摸状态 |
| --- | --- | --- |
| `07` | 关闭图像刷新 | 图像底图停留，文字、FPS、按钮继续刷新，识别与坐标发送持续执行 |
| `08` | 开启图像刷新 | 图像底图恢复实时更新，显示“屏显开” |

`read_display_command()` 每次读取当前已收到的字节，按顺序解析有效指令，并以本次读取的最后一个有效指令设置状态。例如连续收到 `07 08`，本次状态设为开启；连续收到 `08 07`，本次状态设为关闭。其他字节保持当前屏显状态。

```c
/* 通过已配置为115200、8N1的视觉串口发送原始字节。 */
uint8_t screen_off[] = {0x07};
uint8_t screen_on[]  = {0x08};
```

指令执行结果通过设备按钮状态和摄像头图像刷新状态体现；主控持续接收的坐标帧仍使用 `0x02` 类型。白平衡校准、边缘阈值调节和预览切换通过GUI操作。

`Comm.send_detect()` 提供以下发送入口。

| 函数传入的Mode值 | 实际消息类型字节 | 5字节数据区内容 | 当前调用关系 |
| --- | --- | --- | --- |
| 1 | `01` | `Data[0] Data[1] Data[2] Data[3] 00` | 保留入口 |
| 2 | `02` | `Data[0] Data[1] Data[2] Data[3] 00` | 当前圆心发送入口 |
| 3 | `03` | `Data[0] Data[1] Data[2] Data[3] Data[4]` | 保留入口 |
| 4 | `04` | `Data 00 00 00 00` | 保留入口 |
| 5 | `04` | `06 06 06 06 06` | 保留入口 |

表内所有入口均使用 `B3 B3` 帧头和 `5B` 帧尾，完整长度均为9字节。`0x03` 入口提供第五个数据字节的发送位置，当前颜色显示使用内部的 `COLOR_NAMES` 和 `_color_state`，主循环固定调用表中的Mode值2。
